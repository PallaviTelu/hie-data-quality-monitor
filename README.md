# HIE Data Quality & Facility Compliance Monitor

A portfolio project that simulates the monthly data-quality and facility-compliance reporting a health information exchange (HIE) team does: which participating facilities are sending data, which have gone quiet, and how clean the data they send is.

> **All data is synthetic.** Facilities, counts, and errors are fictional and generated by a seeded script. This project is not affiliated with, and does not reflect the real data or systems of, any actual HIE, including NC HealthConnex. It works at the monthly-extract level and does not parse raw HL7 messages.

## What it shows
- **Connection health:** % of expected facilities reporting each month, facilities silent for 30+ days, and the month-over-month change.
- **Data quality:** error rate by error type, error rate by facility type, and the top-10 worst-offender facilities over the trailing 3 months.
- **Pipeline checks:** a 10-check validation scorecard (ID formats, date formats, duplicates, missing or out-of-range counts, unknown facility IDs, silent facilities).

## How it works
```
scripts/generate_data.py   ->  data/raw/*.csv          (synthetic, seeded, deliberately messy)
scripts/run_pipeline.py    ->  loads raw CSVs into SQLite, runs sql/*.sql, writes data/clean/*.csv
sql/00_config.sql              thresholds (3% error rate, 30 silent days, record-count range)
sql/01_clean.sql               standardize IDs, months, dates; quarantine bad rows; de-duplicate
sql/02_facility_month.sql      facility x month status grid; current facility status
sql/03_monthly_summary.sql     KPIs, month-over-month change, error rollups, worst offenders
sql/04_validation_checks.sql   data-quality scorecard
docs/SOP.pdf                   one-page monthly run procedure
docs/TABLEAU_BUILD_GUIDE.md    step-by-step dashboard build from data/clean/*.csv
```

### Defects injected into the raw data (and handled in SQL)
Inconsistent facility IDs (`fac-007`, `FAC007`), mixed month and date formats, exact and conflicting duplicate rows, missing record counts, negative and implausibly large counts, unknown facility IDs, and facilities that stop sending data for 1 to 3 months. Every quarantined row is written to `data/clean/rejected_rows.csv` with a reason.

## Run it
Requires Python 3.9+ (standard library only for the pipeline; `reportlab` and `pypdf` only to rebuild the SOP PDF).
```bash
python scripts/generate_data.py     # optional: regenerates the same synthetic data (seed 42)
python scripts/run_pipeline.py      # cleans, validates, summarizes, exports data/clean/*.csv
python scripts/build_sop_pdf.py     # optional: rebuild docs/SOP.pdf from docs/SOP.md
```
To process a new month, replace the files in `data/raw/` and rerun `run_pipeline.py`; the checklist is in `docs/SOP.pdf`.

## Limitations
- Synthetic data, so the numbers show the method, not real-world performance.
- Thresholds (3% error rate, 30 silent days) and the escalation path in the SOP are illustrative.
- Tableau Public cannot auto-refresh local files, so the dashboard refresh is a manual re-publish. A production setup would use a scheduled data source.
